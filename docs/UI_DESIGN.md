## 1. 設計方針

1. **紙のメモの代わり**：準備→買い物→終える→次回準備を、迷わず片手で完結させる。
2. **高齢の利用者を前提に**：大きな文字、48px以上の押せる領域、色だけに頼らない表示。
3. **画面に説明文を置かない**：アイコン・数字・形・短い言葉で伝える。
4. **1つの色に1つの意味**：墨＝押せる・選択中、緑＝済んだ・そろった、黄＝未確定、赤＝問題・取り消せない操作、青／ベージュ＝担当（自分／相手）。
5. **温かく、毎日使いたくなる**：紙のような温かい白、見出しと数字の丸ゴシック、そろったとき・終えたときの小さな手応え。
6. **未検証のリスクを解決済みとして扱わない**：未確定の状態を表示できる形にするが、技術的成立はPoCで確認する。

## 2. 判定できるルール

| 区分 | ルール |
|---|---|
| 文字 | 本文の最小15px（タブ名のみ14px）、商品名20px、見出し30px。rem指定で端末の文字サイズに追従し、200%で欠けない |
| 押しやすさ | 押せる領域48×48px以上、主ボタン52px、商品行64px以上、隣の操作との間隔8px以上 |
| コントラスト | 文字4.5:1以上、図形と枠線3:1以上 |
| 画面幅 | 320・375・390・414pxで崩れない（横スクロールなし、ボタンの文言が欠けない） |
| 説明文 | 常設の説明文は0。例外は確認ダイアログの1文、招待時のメール共有の告知（AC-03-6）、反映されなかった理由の1行（AC-23） |
| ボタン | 墨で塗ったボタンは1画面に1つまで（送信の↑と右下の＋を除く）。横幅いっぱいのボタンはシート・ダイアログ内と、全部そろったときの「買い物を終える」だけ |
| 色 | 緑はボタンに使わない。赤は削除・エラーだけ。黄は未確定だけ |
| 書体 | 2種類まで（本文＝端末標準、見出し・リスト名・数字＝丸ゴシック） |
| 形 | 丸＝購入チェック（緑）、角丸四角＝複数選択（墨、未購入の引き継ぎだけ） |
| トークン | 色・書体・余白は `tokens.css` からのみ使う。直接の色指定はstylelintで禁止 |

## 4. 表示の基本ルール

- **視点**：各端末で自分は「自分」、相手は呼び名（相手が参加時に付けた、相手に表示される名前）。担当の切替は「自分／相手／すべて」で、開いたときは「自分」。頭文字は自分＝「自」（青）、相手＝呼び名の1文字目（ベージュ）。この色の割り当てはどの端末でも同じ。
- **オフライン**：オンライン必須の操作（追加・編集・作成・終了・削除・定番・設定）は、ボタンを隠さず灰色にする。押すと「オフラインのため使えません」と表示する。購入チェックだけはオフラインで使える。
- **数量**：2以上のときだけ行の右端に「×2」。1は表示しない（追加・編集では常に表示）。単位は付けない。
- **数と日付**：数には「品」を付けて日付と区別する（「3/7 品」）。日付は「11月23日（月）」の形で、曜日は日付から計算する。
- **購入済み**：「購入済み n」欄にまとめ、行に「購入済み」のラベルは付けない。取り消し線も使わない。

## 5. 画面ごとの仕様

### S-10 買い物リスト

- 構成は、日付の行、見出し「買い物リスト」、「利用中 n／履歴 n」の切替。
- **利用中のカード**：お店アイコン（44px）、リスト名（丸ゴ）、「お店 · 3/7 品」、進捗バー、右端に残りの数（ラベルなし、読み上げは「あと4品」）、未送信があれば「未送信あり」。
- **履歴**：「2026年11月」の見出しで区切り、新しい順。行はアイコン、リスト名、「お店 · 2/3 品」。見出しの年月は、リストを終えた日で決める。
- 右下に「＋ リスト」（作成シートを開く）。

### S-11 リストを作成（シート）

- **どのお店？**：アイコン付きチップ＋「＋ 購入先」。押すとその場で追加し、追加したお店を選択する。
- **いつ買う？**：「明日 24日（火）」（初期選択）と「ほかの日」。「ほかの日」でアプリ内カレンダーを開く。7列、マス44px、過去は無効、今日に枠、今月より前には戻れない。端末標準の日付選択は使わない。
- **名前**：「名前　11月24日（火）　［変更］」の1行。何もしなければ購入予定日が名前になる。「変更」で入力欄を開き、空に戻すと日付に戻る。50文字以内。
- 購入予定日は名前を作るためだけに使い、保存しない。
- 作成すると、そのリストを開く。

### S-12 買い物画面

- **ヘッダー（固定）**：戻る・お店アイコン・リスト名・お店名・右上「…」（灰色の丸36px）。
- **ヘッダー直下（固定）**：状態の帯、担当の切替（件数は未購入数）、進捗「（バー）3 / 5」（表示中の担当の範囲）。
- **商品行**：左＝チェック（56×60）、中央＝本文（押すと編集）、右＝数量（2以上のみ）。「すべて」では担当の頭文字を出す。並び順は追加順。
- **追加（QuickAddBar）**：画面下に入力欄と↑を固定する。
  - 入力欄を押すと、そのお店の定番のうちリストにないものが候補として出る（「牛乳 ×2」の形）。文字を打つと絞り込む。
  - 候補を押すか、名前を確定すると即追加する。数量は定番のいつもの数量（なければ1）、担当は表示中の人（「すべて」なら自分）。
  - 同名（nameKeyが一致）は合算する。担当はそのまま、購入済みなら未購入に戻す。
  - 合算後9超・101文字以上のときは追加せず、入力欄の上に短いエラーを出す。
  - IME変換中のEnterは無視する（`isComposing` / keyCode 229）。
- **追加の後**：トースト「納豆 を追加［取り消す］」「牛乳 ×3（合算）［取り消す］」を入力欄の直上に6秒出し、該当行を1.8秒光らせる。
- **そろったとき**：表示中の担当の未購入が0になったら「そろいました」、全体なら「全部そろいました」と出す。
- **買い物を終える**：
  1. 何もチェックしていない間は出さない。
  2. 1つ以上チェックしたら、リストの最後に枠線のボタンで出す。
  3. 全部そろったら、入力欄の上に墨のボタンで出す（②は消す）。
  4. 「…」の中には常にある。
  - 確認ダイアログを毎回出す：「買い物を終えますか」「『11月23日（月）』は履歴に移り、変更できなくなります。花子の未送信のチェックも反映されません。」［買い物を終える］［キャンセル］
- **終えた直後**：かごの線画、「おつかれさまでした」、カゴに入れた品数。残りがあれば「残りn品を次のリストへ」を出す。

### S-14 商品の編集（シート）

- 名前、数量（−／＋、1〜9）、担当（自分が先頭）、保存、定番に登録、削除（シート内で2段階確認）。
- 名前の変更で重複する場合は、合算せず拒否する（FR-018）。
- 終了済みのリストでは読み取り専用にし、「定番に登録」だけを出す（FR-036）。登録先はリストが今参照しているお店。数量1で登録する。

### S-15 その他（「…」）

- **利用中**：購入先を変更／未購入を新しいリストへ／買い物を終える／リストを削除（赤）。
- **終了済み**：未購入を新しいリストへ／履歴を削除。
- **削除の確認**：「『11月23日（月）』を削除しますか」「商品n品も消えます。花子の画面からも消えます。元に戻せません。」

### S-18 未購入を新しいリストへ

- 元のリスト1件の未購入だけを、角丸四角で選ぶ（初期は全選択）。
- 購入先は元と同じで変更不可（鍵アイコン）。
- 名前の行は作成シートと同じで、初期は明日の日付。元のリストは変更しない。

### S-20/21 定番

- お店の切替（アイコン付きチップ）。
- 行は商品名（20px）＋いつもの数量（2以上なら×N）。押すと編集シート（名前・お店・いつもの数量・削除）。右下「＋ 定番」。
- 定番からリストへの追加は、買い物画面の候補だけで行う。
- 重複は正規化後の名前で、同じお店の中で判定する。編集・削除をしても、リストの商品は変わらない（FR-014）。

### S-22 購入先

- 行はアイコン・名前・「使用中／未使用」。押すと編集シート（名前・アイコン12種・削除）。
- 使用中のお店は「使用中のため削除できません」。右下「＋ 購入先」。
- 名前の重複は、前後の空白を除いて判定する（FR-011）。
- アイコン（12種）：カート・薬・パン・魚・野菜・日用品・工具・衣類・カフェ・ギフト・お店（未設定時）・本。

### S-01〜S-04・S-35 認証・参加（プロトタイプ外の画面）

- **S-01 ログイン**：アプリ名、「Googleでログイン」。パスワードは持たない。
- **S-02 はじめに**：見出し「はじめに」、呼び名（初期値はGoogleの表示名）、［グループを作成］。招待された人は届いたリンクを開く。
- **S-03 参加申請**：見出し「グループへの参加申請」。申請の前に「管理者に共有される情報：Googleアカウントのメールアドレス（実際の値を表示）・呼び名」を必ず表示する（AC-03-6）。呼び名の入力、［メールアドレスを共有して申請］、申請できる期限（例：11月24日（火）14:30まで）。
- **S-04 承認待ち**：「承認を待っています」と申請日時、［状態を確認］。無効になった場合は「この申請は無効になりました」と短い理由（リンクの取消・他の人の承認）を出し、新しい招待リンクを管理者に依頼するよう促す。承認前はグループの内容を表示しない。
- **S-35 グループから外れました**：端末に保存されたグループの内容を消してから表示する。送信できなかったチェックは反映されていないことを1行で伝え、［はじめに戻る］。

### S-30〜S-36 設定・グループ

- **設定**：メンバー（n/2人）・購入先（n件）・呼び名・ログアウト・アカウントを削除・データの取り扱い。
- **メンバー（管理者）**：
  - 相手を「外す」。確認ダイアログで、自分に移る担当の件数を示す。
  - 相手がいなければ「招待リンクを発行」。期限（例：11月24日（火）14:30まで有効）・共有・コピー・取消。
  - 参加申請（呼び名・メール）を承認／拒否する。1人を承認すると、ほかの申請とリンクは無効になる。
- **メンバー（一般）**：外す・招待は出さない。アカウントを削除する前に「グループから抜ける」が必要（第10章）。
- **呼び名**：相手に表示される名前。初期値はGoogleの表示名。
- **グループ削除**：削除されるもの（リスト・定番・購入先・メンバー・招待）を確認し、チェックを入れる → 削除中 → はじめに。完了を確認できるまで成功とは表示しない（PoC-04）。
- **S-35**：除外・削除を検知したら、端末のグループデータを消してから「グループから外れました」を出す。
- **データの取り扱い**：2人だけが見られること、申請時にメールが管理者に伝わること、削除の扱い（記録・バックアップは30日以内の削除を目標）、Googleアカウントは削除しないこと。

## 6. 状態別の表示

### 6.1 同期状態（商品単位、FR-030〜034・FR-037・RISK-01〜03・RISK-09）

| UI状態 | 入る条件 | 表示と操作 |
|---|---|---|
| 反映済み | サーバーの確定状態と表示が一致 | 表示なし |
| 未送信 | オフラインでチェックを変更（もう一度押して元に戻すと解除） | 行に「未送信」。オフラインの帯に「未送信 n」 |
| 送信中 | 通信が戻り、送信を開始 | 帯「送信中…」。成功表示は確定後 |
| 送信失敗 | 一時的な失敗 | 端末に保持し、自動で再試行。帯「n件 送信失敗［再試行］」 |
| 反映されませんでした | 確定的な拒否（終了・削除・権限喪失） | 帯「n件 反映されませんでした・先にリストが終了していました［確認］」。表示はサーバーの状態に戻す。確認するまで消さない |

- オンライン中に相手が終了・削除した場合は、購読の更新で閲覧のみ（または一覧へ戻す）に切り替え、トーストで知らせる。
- オフラインの判定は、ブラウザの判定だけに頼らない。Firestoreの書き込み・購読の結果とあわせて判断する（PoC-01/03）。UIは `syncState` を受け取るだけにする。

### 6.2 画面の状態

| 状態 | 表示 |
|---|---|
| 読み込み中 | 担当の切替は表示し、行はスケルトン |
| 空（商品なし） | かごの線画＋「商品なし」。追加は下の入力欄 |
| 表示中の担当がそろった | 「そろいました」（緑の地） |
| オフライン（保存済み） | 帯「オフライン（未送信 n）」。入力欄は灰色 |
| 保存されていないリスト | 「オフラインのため開けません［再読み込み］」（PoC-03） |
| 終了済み | 帯「11月23日（月） 終了」（鍵）。チェック不可、商品からの定番登録のみ |
| 履歴なし・利用中なし | 「履歴なし」「利用中のリストなし」 |

### 6.3 入力の検証と文言

## 7. デザインシステム

## 10. 実装時に確認する事項

| 事項 | 確認すること |
|---|---|
| グループから抜ける（一般メンバー） | 確認→抜けた後の画面。担当の再割当（FR-007）と、抜けた側の端末データの消去 |
| 相手がリストを削除したとき | 開いている側の表示（一覧へ戻す＋トースト）、未送信チェックの「反映されませんでした」（RISK-09、PoC-01 P01-08） |
| 「取り消す」と同時操作 | 相手に届いた変更を取り消す場合の整合（RISK-02、PoC-01 P01-10）。成立しなければ取り消しの範囲を狭める |
| iPhoneのキーボード | 入力欄と候補パネルがキーボードに隠れない（visualViewport）。PWA・Safariの両方 |
| 日本語入力 | 変換確定のEnterで追加されない（iOS・Android・各IME） |
| 小さい画面・大きい文字 | 320px、文字サイズ最大での崩れ |
| 丸ゴシックの配信 | サブセット化とService Workerでの保存、またはiOSのみヒラギノ丸ゴ。オフラインでも表示が崩れない |
| 家族による試用 | 実装後、実機で「牛乳を2本追加」「自分の担当をチェック」「買い物を終える」を試してもらい、迷った点を記録・改善 |
