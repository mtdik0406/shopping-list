# 0002. 要件の範囲内で具体化した仕様（A1〜A10）

- 状態：承認
- 日付：2026-11-24
- 関連：FR-002、FR-004〜007、FR-018〜020、FR-030、FR-036、AC-03、AC-13、AC-14、RISK-02、PoC-01（P01-10）、PoC-02

## 背景

実装の準備で要件・UI設計・プロトタイプを突き合わせたところ、要件が値や振る舞いを決めていない箇所と、文書どうしが食い違う箇所が見つかった。要件の範囲内で、次のように具体化する。各項目は A1〜A10 の番号で参照する。

## 決定

| No. | 事項 | 決定 |
|---|---|---|
| A1 | 呼び名の文字数の上限 | 前後空白除去後1〜20文字 |
| A2 | 現在のメンバーにいない担当者（脱退・除外した人）の表示 | 「以前のメンバー」と表示する。後から参加した人の呼び名で表示しない |
| A3 | 参加申請に含まれるメールアドレス | 承認・拒否・無効が確定した時点で、申請のメールアドレスと呼び名を削除し、状態と理由（リンクの取消・他の人の承認など）だけを残す。申請文書は、申請者が結果を確認した時点か一定期間の経過後に削除する（期間はPoC-02で決める）。membersにメールを写さない |
| A4 | FR-036で参照先の購入先が存在しない異常データ | 購入先のチップを選ぶシートを1枚追加して登録先を選ばせる |
| A5 | 「取り消す」の範囲 | 自分の直前の追加・合算だけを、6秒以内・オンライン中・相手がその商品を変更していない場合に限り取り消す。相手が変更していたら取り消さず理由を表示する。最終形はP01-10の結果で決める |
| A6 | 未送信のチェックがあるときのログアウト | 失われることを確認ダイアログで警告し、確認後に端末の保存データを消去する |
| A7 | 「事前保存済みリスト」の意味 | 一度オンラインで開いたリスト。加えて、起動時に利用中リストの商品を先読みする |
| A8 | 合算後の担当の示し方（FR-020） | 合算した行が現在の担当表示に出ない場合だけ、トーストに「（担当 ○○）」を付ける |
| A9 | 丸ゴシックの配信 | Zen Maru Gothicの太字だけを自前配信し、Service Workerで保存する。本文用のWebフォントは読み込まない |
| A10 | 有効な招待リンクの本数 | 同時に有効なリンクは1本 |

あわせて次を決めた。

- プロトタイプ（`ui-prototype/Main.dc.html`）と`UI_DESIGN.md`が食い違う場合は、`UI_DESIGN.md`と`tokens.css`を優先する。プロトタイプに残る定番画面の複数選択は作らない。

## 根拠

- 要件と受け入れ条件の内容を変えずに、実装とテストで判定できる形にするため。
- A5は、P01-10のPASS条件（相手の確定済みの変更を失わない）を満たせる範囲に限った。

## 影響

- `ARCHITECTURE.md`のデータモデル（members.nickname、requests）と、`UI_DESIGN.md`の画面の仕様は本ADRに従う。
- A3の期間はPoC-02、A5の最終形はP01-10の結果で決め、必要なら本ADRを置き換える。

## 見直し条件

- PoC-01・02の結果、上の決定が成立しないとき。
- 実機での利用で、表示や操作に迷いが見つかったとき。
